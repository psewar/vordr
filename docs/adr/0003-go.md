# Go for agent and hub

Backfilled on 2026-10-30, decided on 2026-10-28. Sources: the operator's project notes (2026-10-28),
`design/architecture.md` section 13.

## Context and Problem Statement

Agent and hub need a language. The agent runs on Linux (amd64, arm64, arm) and Windows, also on small devices such as
Raspberry Pis.

## Decision Drivers

* One static binary without a runtime on every host.
* Small size and memory use.
* Reuse the proven parts of an earlier agent project.

## Considered Options

* Go
* Rust

## Decision Outcome

Chosen option: Go (the operator, 2026-10-28).

Measured with a core of TLS, WebSocket, Ed25519 and JSON: 6.2–7.0 MB per target (gzip 2.6–2.9 MB), 12 MB
RSS after one TLS connection. Rust would be smaller (estimated 1.5–3 MB and 2–5 MB RSS, not measured: Rust was not
installed in the build environment). That only pays off on devices with very little memory, and those get no agent
([ADR-0013](0013-scope-limits.md)). Go lets us take over parts of the earlier agent
([ADR-0012](0012-copy-parts-of-the-earlier-agent.md)).

### Consequences

* Good, because `CGO_ENABLED=0` and `-trimpath` give static binaries for all targets from one build.
* Good, because identity, tunnel and self-update from the earlier agent fit without translation.
* Bad, because the binaries are larger than Rust would be.
* Bad, because holes in the Go standard library need a rebuild. Go 1.27.1 had 11 reachable vulnerabilities, so
  `go.mod` pins a patched toolchain (`toolchain go1.27.3`).

### Confirmation

`build.sh` builds all targets with `CGO_ENABLED=0`; `go.mod` pins the toolchain.
